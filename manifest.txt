# claude-harness sync manifest
# One row per file. Pipe-separated: kind|tier|repo-path|live-path
#
#   kind      sync      copied from a live Claude config file; export.sh and
#                       import.sh diff these two paths in both directions.
#             authored  written for this repo; no live counterpart, so the
#                       sync scripts skip it. install.sh still installs the
#                       ones whose live-path is not "-".
#             authored-win  authored, and WINDOWS ONLY. This is the platform
#                       convention: rows have no platform column, so the kind
#                       carries it. bin/install.sh installs an authored-win row
#                       only when it runs with --windows (passed, or detected
#                       from a Windows shell); on macOS and Linux it skips them
#                       and reports how many. Every other reader is unaffected:
#                       export.sh and import.sh walk "sync" rows only, and
#                       guard/scan.sh does not read this manifest at all.
#                       Adding a platform is therefore one new kind here and
#                       one case in install.sh, nothing else.
#   tier      lowest install tier that includes the file (install.sh --tier N
#             installs every row with tier <= N). Tier 3 rows are printed,
#             not copied.
#   live-path relative to the Claude config dir ($CLAUDE_CONFIG_DIR, default
#             ~/.claude). "-" means the file never leaves the repo.
#
# This manifest is the allowlist. guard/scan.sh and the sync scripts read it,
# and nothing outside it belongs in the repo.

# --- tier 2, Windows only: the PowerShell 7 guard twins ---------------------
# Same guards, same policy, written in PowerShell because which shell the agent
# spawns a hook command through on Windows is undocumented, and a bare .sh path
# that no shell runs is a guard that silently never fires. There is exactly one
# copy of each twin and it lives under copilot/, where it was first written;
# bin/install-copilot.sh reaches the same files through manifest.copilot.txt.
# The .sh guards are installed alongside them on Windows too: they are harmless,
# and Git Bash may well run them.
#
# The Windows settings template wires the four guards as
# "pwsh -NoProfile -File __CLAUDE_HOME__/hooks/<name>.ps1". It carries no
# PostToolUse block: log-skill-fire has no PowerShell twin and is logging only.
